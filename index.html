UniVMS

Oct 2026 to now, version 1.4.16

  • Source code
  • Releases

A desktop client for watching and managing security cameras from several brands in one place. Each brand speaks its own protocol, so the core of the app is a driver layer that turns all of them into one model for live view, playback, PTZ control and events.

  • Drivers for Hikvision, Dahua, Hanwha, Uniview, Reolink and DW Spectrum, over their HTTP APIs or native SDKs loaded through FFI.
  • One event center fed by every device's alert stream, with online/offline monitoring and snapshots on each alert.
  • Playback with a zoomable timeline, synchronized cameras and MP4 clip export through FFmpeg.
  • Self-updating installers for Windows, Debian and Fedora; 24 releases in its first three weeks. A company build, SightWatch VMS, signs in to the SightWatch platform.

Node.js, Electron, FFmpeg, koffi (FFI), WebGL, GitHub Actions

TwinLine

Sep 2026 to now, version 1.4.37

  • Source code
  • Releases

A two-line SIP softphone for Windows and Linux. The SIP stack is written from scratch rather than taken from a library: message parsing, transactions, digest authentication and SDP negotiation, plus RTP with a jitter buffer.

  • Two accounts registered at once, several calls per line, hold, swap and blind or attended transfer.
  • Conference calls mixed on the user's machine, so one participant can be held or dropped while the rest keep talking.
  • Optional call transcription that runs entirely offline.
  • Passwords encrypted with the operating system's key store, sandboxed windows under a strict content security policy, and two published security audits.

Node.js, Electron, SIP, RTP, SDP, sherpa-onnx

Camera fleet tools

Oct 2026 to now

Internal, source is private

Services for operating the video analytics boxes installed at client sites, all from one management machine.

  • An MCP server so staff can check every box's health, read its configuration and restart services by asking in a chat.

Neolink

Oct 2026, 25 commits

  • My commits
  • Fork

Neolink is a Rust proxy that serves Reolink cameras, which only speak a proprietary protocol, as standard RTSP streams. I maintain a fork with fixes for running it against busy recorders over relayed connections.

  • Channels on the same recorder now share one login, since recorders cap their sessions.
  • Lifted a relay throughput cap of about 90 kB/s by changing how UDP acknowledgments report latency and enlarging socket buffers.
  • One RTSP thread per client, so a stalled viewer no longer freezes every other channel, and streams are torn down when their clients leave.
  • Video timestamps taken from the camera's own clock, which fixed video playing up to twice as fast after dropped frames.

Rust, GStreamer, RTSP, UDP
